## 01 · Opening｜项目开场（30 秒）

大家好，我们的项目是 FallGuard，一个基于摄像头的跌倒检测原型。我们做了两方面的工作：一是研究人体姿态不完整时，怎样利用一小段连续动作判断跌倒；二是把姿态提取、跌倒分类和记录保存全部放到树莓派上，让它在断网时仍然能独立工作。

我们还接入了 Hailo 算力板来加速姿态提取，并实现了恢复联网后的记录补传。接下来，我会介绍模型设计、实验结果，以及树莓派与云端如何配合。

**指图提示：** 右侧的 20.56 fps 是本地视频完整处理流水线的吞吐量；11.9 倍是同一个 YOLOv8s-pose 模型使用 Hailo 与 CPU ONNX 两种后端的对比。不要把这两个数字说成单独分类器的速度。

## 02 · Care setting｜研究动机与贡献（35 秒）

跌倒检测的难点是，跌倒和坐下、弯腰等正常动作，可能出现相似的身体姿势。因此，仅看单帧不够，还要结合前后动作。最近的研究使用时序卷积、注意力和状态空间模型来处理动作序列，也有工作引入骨架几何信息和姿态置信度。

我们的模型关注姿态观察缺失的情况，希望从邻近时刻中补充判断依据。在系统层面，我们考虑的是：如果网络突然断开，检测不能随之停止，已经产生的记录也应保留下来。

**指图提示：** 结合本页的相关研究与贡献列表，讲清“时序建模”和“离线运行”这两条主线。本页不展开数据集。

## 03 · System｜系统如何运行（40 秒）

请看这张流程图。摄像头或本地视频首先提供画面，Hailo 算力板提取人体关键点，然后由树莓派 CPU 上的 MaskedBiMamba 模型对一秒钟的姿态窗口进行分类。树莓派根据结果更新告警状态，并把记录写入本地 SQLite 数据库。

树莓派还有自己的操作页面，所以没有互联网时也能查看检测状态。云端负责汇总记录和事件回看。云端保存成功后返回确认，本地再更新上传状态；传输中断时可以重试。这样，检测与网络传输就能分别运行。

**指图提示：** 顺着输入、姿态提取、分类、本地存储、云端的方向讲。强调算力板主要加速姿态提取，分类仍在树莓派 CPU 上执行。

## 04 · Model｜模型改进的原理（50 秒）

模型输入包含十二个人体关节，每个关节保留归一化后的横纵坐标和置信度。训练时，我们随机遮蔽一部分帧，让模型学习利用其余时刻的信息。输入经过特征映射和时序注意力后，分别进入前向与后向 Mamba 分支，再把两个方向的结果对齐融合。

最后是质量加权汇聚。模型根据关节平均置信度、可见关节比例和人体检测置信度，学习每一帧的权重，再完成分类。公式中的权重越高，该帧对最终表示的贡献越大。

我们的工作是在已有 Mamba 算子的基础上，组合这些模块并验证它们的作用。后面的消融实验会说明哪些模块带来了收益。

**指图提示：** 按结构图从左到右讲，必要时点击放大。双向处理发生在已经缓存的一秒窗口内；它不是提前读取尚未发生的动作。质量权重是学习得到的，不是简单把低置信度帧全部删除。

## 05 · Evaluation｜数据集与实验设置（40 秒）

主要实验使用 CAUCAFall 和 GMDCSA-24，共十四个受试者分组。我们按受试者划分训练与测试数据，采用四折交叉验证和三个随机种子，因此每个模型对应十二次评估。Le2i 既有单独的基线实验，也作为外部数据评估泛化能力。树莓派部署测试则使用四十段合成视频。

评价包括窗口级、视频级和事件级指标。精确率回答“报出的跌倒有多少是真的”，召回率回答“实际跌倒有多少被检出”，F1 综合考虑二者。不同实验的任务和统计口径不同，所以分别展示。

**指图提示：** 展开指标公式时，TP 表示正确检出的跌倒，FP 表示误报，FN 表示漏报。误报每小时按实验视频的评价时段折算，不能直接当成全天真实监护的误报频率。

## 06 · Baselines｜主要结果比较（40 秒）

这里可以看到，模型排名会随着评价指标变化。Transformer 编码器的干净数据窗口 F1 和事件召回率最高。MaskedBiMamba 的窗口精确率最高，未匹配告警事件的折算频率最低，视频 F1 也接近 Transformer。

所以，我们的主要结果是精确率、灵敏度和误报之间的权衡。MaskedBiMamba 的窗口精确率为 0.6048，视频 F1 为 0.7632；Transformer 的窗口 F1 为 0.6581。对于监测系统，降低误报有价值，但也需要同时检查是否漏掉更多跌倒。

**指图提示：** 用下拉菜单切换 Window F1、Window precision 和 False alarms per hour。误差线表示重复评估的样本标准差。图中的相对优势不代表绝对误报水平已经适合实际长期监护。

## 07 · Ablations｜各改进模块是否有用（35 秒）

我们在相同划分和随机种子下，测试了十个模型变体。去掉后向分支或者时序注意力后，窗口 F1 下降，误报增加，这说明两个模块对组合模型有帮助。

其他模块的影响没有那么一致。例如，去掉训练遮蔽后，干净数据的窗口 F1 反而有所提高；去掉质量汇聚后，干净数据的视频 F1 也有所提高。因此，各模块影响的是模型的不同表现，需要结合干净数据、缺失数据和误报一起判断。

**指图提示：** 首先指出完整模型，再比较去掉后向分支和注意力的变体。不要把所有模块概括成“每个指标都提升”。需要具体数值时展开本页表格。

## 08 · Robustness｜姿态缺失时的表现（40 秒）

模型比较明显的优势出现在缺帧条件下。当百分之三十的姿态帧被移除时，MaskedBiMamba 的窗口 F1 为 0.6276，TCNTE 为 0.4361。外部 Le2i 数据上也观察到了相似趋势。

这表明，前后时刻的信息可以在一定程度上补偿缺帧。不过，持续缺失身体关节更难处理，因为整个序列中的人体几何信息都减少了。这里测试的是提取后的姿态扰动；摄像头视角、光照等变化，还需要另行评估。

**指图提示：** 先显示主实验、Frame drop 和 Window F1，指向 30% 的位置；再根据时间切换外部数据或 Joint drop。横轴越往右，扰动越强。

## 09 · Edge deployment｜树莓派离线检测（45 秒）

我们在没有外部网络接口或路由的情况下，运行了完整检测流水线。使用同一个 YOLOv8s-pose 模型比较时，CPU ONNX 的吞吐量是每秒 1.73 帧，Hailo 是每秒 20.56 帧，约提升 11.9 倍。跌倒分类仍由树莓派 CPU 完成。

在四十段合成视频中，三十九段产生了分类结果：二十段跌倒视频被判为阳性，十一段正常视频判为阴性，八段正常视频出现误报，还有一段没有输出。如果进一步要求在标注的跌倒时段内检出，二十段跌倒视频中只有十四段满足要求。

**指图提示：** 左右对照速度图和检测统计，点击结果图可放大。20/20 是整段视频中出现过阳性预测的口径；14/20 才是在标注跌倒时段内的检出情况。保留这一区别，回答会更准确。

## 10 · Cloud recovery｜断网记录与恢复补传（40 秒）

接下来验证的是记录是否能保留并补传。在一次三十秒的上传链路中断中，树莓派积压了十七条记录；恢复链路后，约 2.83 秒首次观察到队列清空。补传测试中的八十五条记录，其编号和原始采集时间都与本地一致。云端重启后重放记录，没有产生重复记录。

此外，强制终止写入进程后，一百条已经提交的记录全部保留。约十分钟的离线回放处理了一万一千多帧，没有报告降频。这些结果说明，本地运行、记录保存和恢复上传这几个环节已经接通并完成测试。

**指图提示：** 2.83 秒指这次中断测试中恢复到队列首次清空的时间，不是所有情况下都能保证的上限。传输时延从窗口末帧采集到云端接收计算，不等于从跌倒开始到告警的时延。

## 11 · Demonstration｜现场演示怎么做（35 秒，演示另计）

现场演示时，我们通过 HDMI 把树莓派直接连接到显示器或投影设备，让观众看到树莓派本地页面。首先确认完整人体在画面中，并且分类窗口计数持续增加。然后断开 Wi-Fi 和网线，展示姿态提取、跌倒分类和本地记录仍然继续。

重新联网后，再查看待上传记录进入云端。如果现场摄像条件不理想，我们可以使用保存在树莓派上的公开或合成视频，并明确说明视频来源。当前汇报网页用于展示项目，真正的检测画面来自树莓派本地操作页面。

**现场动作：** 先显示本地画面和计数，再断网；观察新记录和待上传数；恢复网络后刷新云端记录。使用本地视频回放时说明这是回放，不把它称为现场真人检测。手机热点或局域网查看方式不能代替“所有网络断开后仍可看到画面”的 HDMI 展示。

## 12 · Conclusions｜结论（35 秒）

这个项目把时序模型研究和边缘设备部署连接起来。模型方面，MaskedBiMamba 在精确率和缺帧条件下具有优势，Transformer 在干净数据的窗口 F1 上更好。系统方面，树莓派能够独立提取姿态、进行分类和保存记录，恢复联网后可以把积压记录送到云端。

后续改进主要是降低误报、提高对新拍摄条件的适应性，并检验更长时间的运行表现。最后的附录保留了全部导出的汇总数据，方便老师进一步查看。谢谢大家。

## A · Data appendix｜答辩查数说明（不计入正文时长）

附录包含 1,853 行导出的汇总数据，可以按实验类型筛选、搜索指标、切换每页条数，也可以下载完整 CSV。这里的行数是汇总结果行数，不是视频数或独立样本数。

常用解释：

- **Window**：模型一次分类使用的时间窗口。
- **Video / clip**：整段视频；一段视频可能含多个窗口。
- **Event**：依据事件匹配规则评价的跌倒或告警。
- **Precision**：TP / (TP + FP)，预测为跌倒的结果中，正确的比例。
- **Recall**：TP / (TP + FN)，实际跌倒中被检出的比例。
- **F1**：2 × Precision × Recall / (Precision + Recall)。
- **Ablation**：去掉或替换某个模块，比较指标变化。
- **Mean ± SD**：多次评估的均值与样本标准差，不是置信区间。
- **Synthetic clips**：合成视频，用于本次边缘流水线测试，不能直接代表真实家庭环境的效果。
